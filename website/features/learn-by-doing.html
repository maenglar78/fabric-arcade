FEATURE

Learn by Doing

Forget tutorial videos. Every Fabric Arcade game spins up real Fabric items in your own workspace, so you learn by clicking Run, not by watching someone else.

📋 What it means in practice

When you arcade.install("fabric-racing-game"), the library uses the Fabric REST APIs to create the same items a Solutions Architect would build by hand: Lakehouses, Eventhouses, Eventstreams, Semantic Models, Notebooks. They live in your workspace, they consume your capacity, and they are yours to keep, modify and break.

That is the trick: instead of reading "this is how Direct Lake works", you end up looking at a real Direct Lake semantic model, opening its TMDL, editing a measure and re-running a validation notebook to see your score change.

🧱 What gets created for you

🏠
Lakehouses
Synthetic but realistic Delta tables (Sales, Date, Customers...) so the games behave like a production model.
⚡
Eventhouses + KQL DB
For Real-Time games: telemetry ingestion, KQL tables and queryable history of every move you make.
🔀
Eventstreams
Pre-wired Custom Endpoint → KQL DB routes. You just publish and start streaming.
📓
Notebooks
Setup, Quest, Check and Dashboard notebooks. Real PySpark / Python code you can edit and reuse.
📊
Semantic Models
Direct Lake models with seed measures and a Time Intelligence calculation group skeleton.
📜
README notebook
Auto-generated post-deploy guide with the exact next steps for the game you installed.

🛠️ Side-effect: you also learn the platform

Because everything is built via the Fabric REST API, the install script doubles as a worked example: workspace lookup, item creation, KQL schema management, notebook upload via InlineBase64. Read the source on GitHub to see how to do all of this in your own pipelines.
