📋 Overview

Welcome, Mayor of Datapolis! Your city is growing fast and the Council needs answers. Build a real Fabric Warehouse and a Power BI semantic model to serve the citizens, district by district.

Each district teaches a core dimensional modeling concept — surrogate keys, conformed dimensions, semi-additive facts, SCD Type 2 — and ends with a boss-level galaxy schema uniting all 3 main facts of your city.

🧩 How You Play (Real Fabric, Not a Simulation)

City Builder is a learning quest: you model real Fabric Warehouse tables and a Power BI semantic model. Every district follows the same loop:

  1. 📖 Read the briefing in the CityBuilder_Mayor notebook (e.g. "Datapolis launched a taxi service — build FactTaxiTrip + DimDate, DimDriver, DimZone, DimVehicle").
  2. 💼 Open the empty Warehouse Datapolis_DW in Fabric and write T-SQL to CREATE the tables and load them from the raw data in Datapolis_LH.
  3. 🔗 Open the Semantic Model Datapolis_Model in Fabric, add the required relationships, and author the DAX measures listed in the briefing.
  4. ⚖️ Back in the notebook, run mayor.inspect_district("taxi") — the Mayor validates your schema via INFORMATION_SCHEMA, runs your DAX measures via the XMLA endpoint, and compares to the expected oracle. Telemetry goes to the Eventhouse.
  5. 📊 The CityBuilder_Dashboard updates live with the city map, your Mayor reputation, and the DAX scoreboard.

📦 What Gets Installed in Your Workspace

arcade.install("city-builder") deploys:

  • 🏠 1 Lakehouse Datapolis_LH — 8 raw datasets (one per district) + 8 expected oracle datasets used for validation.
  • 🏛️ 1 Warehouse Datapolis_DW — pre-created empty. You add Fact* and Dim* tables yourself via T-SQL.
  • 📐 1 Semantic Model Datapolis_Model — pre-created empty, bound to the Warehouse. You add relationships and DAX measures in the Fabric UI.
  • ⚡ 1 Eventhouse Datapolis_EH with KQL Database CityData and table CityEvents — Mayor's telemetry for every inspection.
  • 📓 3 Notebooks:
    • CityBuilder_Seed — generates raw + expected datasets (run once).
    • CityBuilder_Mayor — district briefings + inspect_district(name) validator.
    • CityBuilder_Dashboard — live city map + reputation + DAX scoreboard.

🤖 What the Mayor (Judge) Checks

  • ✅ Grain — fact row count matches raw event count
  • ✅ Keys — surrogate INT IDENTITY, no NULL foreign keys
  • ✅ Relationships — many-to-one, single direction (no rogue bidirectional)
  • ✅ Star vs Snowflake — penalty if you snowflake without reason
  • ✅ DAX measure values — executed via XMLA EVALUATE, compared to oracle
  • ✅ Performance — query time under threshold
