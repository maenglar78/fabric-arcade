Calc Groups Cathedral

Build a cathedral of Calculation Groups on a real Fabric Semantic Model. 12 KPI variations, minimum base measures, judge runs DAX over XMLA.

Difficulty⭐⭐⭐ Advanced
Deploy Time~5 min
Complete Time~60 min
Status🚧 In Development
"An apprentice writes a measure for every KPI variation. A master architect carves one calculation group and lets the cathedral build itself."

📋 Overview

You are the Chief Architect of the Vertipaq Cathedral. Twelve KPI variations need to be exposed on a real Fabric Semantic Model: Current, LY, YoY, YoY%, YTD, MTD, QTD, Rolling12, vs Budget, vs Budget %, Best Month, % of Total.

The lazy way: 12 base measures × 3 KPIs = 36 measures. The architect's way: 3 base measures + 1 Calculation Group with 12 calc items. The judge will test every combination via XMLA, and your score is elegance = 1 - (measures_you_wrote / 36).

🚀 Quick Start

In active development. When released, the loop will be:

from fabric_arcade import arcade

arcade.install("calc-groups-cathedral")
# Deploys: Lakehouse with Sales/Date/Customer/Budget, empty Semantic Model,
#          Eventhouse telemetry, 3 notebooks. Open CalcGroups_Cathedral.

🧩 How You Play (Real Semantic Model, Real DAX)

  1. 📖 Open CalcGroups_Cathedral notebook — read the 12 KPI specs with expected values for test dates.
  2. 🏛️ Open Cathedral_Model Semantic Model in the Fabric Web UI. Tables are already there (Sales, Date, Customer, Budget) with relationships.
  3. ✍️ Write your base measures (e.g. Sales Amount, Budget Amount) — start with the absolute minimum.
  4. 🧮 Create one or more Calculation Groups (e.g. Time Intelligence, Comparison) with calc items that wrap the base measures.
  5. ⚖️ Run judge.submit_all() — it executes 12 DAX queries via XMLA, one per KPI variation, on locked test dates. Returns pass/fail per KPI + elegance score.
  6. 📊 CalcGroups_Dashboard shows your progress, KPIs unlocked, measure count, elegance %, and the Architect Rank board.

✅ Why This Game Is Truly Implementable

Unlike Preview games, every building block here is verified to work with current Fabric APIs and MCP servers:

  • ✅ Semantic Model creation via Fabric REST items POST with inline TMDL — already used by Racing.
  • ✅ Calculation Groups in TMDL — stable, public syntax.
  • ✅ DAX execution via XMLA — MCP powerbi-model dax_query_operations is configured and tested.
  • ✅ Measure count from TOM — measure_operations lists all measures live.
  • ✅ Telemetry → Eventhouse — same proven pattern as Racing.
  • ✅ Zero exotic dependencies — no crypto, no Spark, no Digital Twin, no ML.

📦 What Gets Installed

  • 🏠 Lakehouse Cathedral_LH — Sales / Date / Customer / Budget tables, 3 years of synthetic data.
  • ⭐ Semantic Model Cathedral_Model — relationships and one trivial seed measure. Calc groups: zero. You build them.
  • ⚡ Eventhouse Cathedral_EH + KQL DB + table CathedralEvents — telemetry of submissions, pass/fail, elegance.
  • 📓 3 Notebooks:
    • CalcGroups_Seed — generates Sales/Budget synthetic data (run once).
    • CalcGroups_Cathedral — 12 KPI briefings + judge.submit_all().
    • CalcGroups_Dashboard — KQL + Plotly: KPIs passed, measures count, elegance %, rank board.

⚖️ What the Judge Checks

  • ✅ Correctness — runs each of the 12 KPI variations via XMLA on locked test dates, compares to expected values (tolerance 0.01).
  • ✅ Calc Group usage — verifies you actually used calculation groups (not 36 hardcoded measures).
  • ✅ Elegance score — 1 − (your_measure_count / 36). Lower measure count = higher score.
  • ✅ No cheating — pre-existing seed measure is excluded from your count; calc items are counted as 1 group, not N.
  • 🏆 Architect Rank — Mason → Sculptor → Architect → Grandmaster.
