📋 Overview

You are Detective Sherlock Graph at Datapolis P.I., the city's last honest investigation agency. Ten cases. Ten mysteries. Each one is solved by modeling the right ontology, ingesting evidence, and writing a KQL semantic query that converges on the one — and only one — suspect.

A great detective doesn't fabricate evidence. The judge rewards ontology minimalism: every entity type you create must earn its place in your solving query.

🧩 How You Play (Real Fabric, Not a Simulation)

Each case follows the same investigative loop:

  1. 📖 Read the noir briefing in the OntologyDetective_CaseFile notebook — victim, time window, evidence available, suspect list.
  2. 🏛️ Open DetectiveOntology in the Fabric Digital Twin Builder UI and add the entity types + relationships you'll need (e.g. Person, Location, PhoneCall, wasAt, called).
  3. 📥 Run the "Ingest Evidence" ready-cell — it will fail loudly if your ontology is missing required types (your first clue).
  4. 🔍 Write a KQL query over the ontology event store that returns exactly one Person — the culprit. Save it to the SOLUTION_QUERY variable.
  5. ⚖️ Call detective.accuse("Mr. Pythagoras") — the judge decrypts the solution (AES-encrypted per player/case), re-executes your query to confirm it actually returns the accused, and scores your ontology minimalism.
  6. 📊 The OntologyDetective_Dashboard updates with cases solved, accuracy, and Detective Rank.

📦 What Gets Installed in Your Workspace

arcade.install("ontology-detective") deploys:

  • 🏠 1 Lakehouse Datapolis_DetectiveLH — 10 case folders with witness CSVs, camera logs, phone records, and solution.json.enc (AES-encrypted).
  • 🌐 1 Ontology DetectiveOntology — pre-created empty in Digital Twin Builder. You build it case by case.
  • ⚡ 1 Eventhouse Datapolis_DetectiveEH with KQL Database DetectiveData and table DetectiveEvents — telemetry of cases, accusations, rank.
  • 📓 3 Notebooks:
    • OntologyDetective_Seed — generates the 10 case bundles (run once).
    • OntologyDetective_CaseFile — noir briefings + ready ingestion cells + detective.accuse(name) judge.
    • OntologyDetective_Dashboard — live cases / accuracy / minimalism / rank.

⚖️ What the Judge Checks

  • ✅ Correct culprit — decrypts solution.json.enc with key SHA256(player_id || case_id || workspace_id)
  • ✅ Supporting query — re-runs your saved SOLUTION_QUERY to confirm it actually returns the accused
  • ✅ Ontology minimalism — entity_types_used_in_query / entity_types_created close to 1.0
  • ✅ Accuracy tracking — prior wrong accusations count against you
  • 🏆 Rank promotion — Rookie → Inspector → Commissioner
